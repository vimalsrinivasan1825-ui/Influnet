## 3. What I fixed in code this session (done, tested, build-clean)

All changes: `tsc --noEmit` ✅ clean · `vitest run` ✅ 98 passing (+20 new) · `next build` ✅ exit 0.

### 3.1 Rate limiting on abuse/cost-prone routes  ✅
- **New:** [`src/lib/rate-limit.ts`](../../apps/web/src/lib/rate-limit.ts) — provider-agnostic limiter. Zero deps; uses an in-process fixed-window floor, and **auto-upgrades to distributed Upstash Redis** when `UPSTASH_REDIS_REST_URL` + `_TOKEN` are set. Fails **open** (never locks users out if the store errors).
- **Applied to:** `POST /api/collabs` (20/min — collab spam), `POST /api/verification` (6/min — each call spends a paid scrape), `POST /api/verification/ownership` (20/min — on top of its per-claim cooldowns), `POST /api/reports` (10/min — report flooding), `POST /api/projects/[id]/payments` (12/min).
- **Tests:** [`tests/unit/rate-limit.test.ts`](../../apps/web/tests/unit/rate-limit.test.ts).
- ⚠️ **Prod note:** without Upstash, the floor is *per serverless instance*, so real limits are looser than configured under scale. Set Upstash (§4.4) for correct enforcement.

### 3.2 Error monitoring (Sentry)  ✅
- **New:** [`src/lib/observability.ts`](../../apps/web/src/lib/observability.ts) — dependency-free Sentry client. **Completely inert with no DSN** (no imports, no network). With a DSN it posts valid Sentry envelopes, fire-and-forget, timeout-guarded.
- **Wired:** every `5xx` from `jsonError()` reports automatically ([`src/lib/api.ts`](../../apps/web/src/lib/api.ts)); the client error boundary ([`src/app/error.tsx`](../../apps/web/src/app/error.tsx)) reports browser crashes; the payments webhook reports processing faults.
- **Tests:** [`tests/unit/observability.test.ts`](../../apps/web/tests/unit/observability.test.ts).
- **Note:** this is the minimal "know when it breaks" layer. You can later adopt full `@sentry/nextjs` (tracing, source maps) without removing this — see §5.

### 3.3 Payments — real Razorpay, env-gated, honest fallback  ✅
Two modes, chosen automatically by whether `NEXT_PUBLIC_RAZORPAY_KEY_ID` is set:
- **Manual (default, no keys):** the payment gate shows an honest notice — *"Payments are handled off-platform (UPI/bank). Influnet does not process this money."* The business marks the step done once paid. **No more cosmetic buttons pretending to take money.**
- **Razorpay (keys set):** the business gets a real **"Pay ₹X securely"** button → Razorpay Checkout → a **signature-verified webhook** records the payment and auto-opens the gate.
- **New files:** [`src/lib/payments/razorpay.ts`](../../apps/web/src/lib/payments/razorpay.ts) (orders + HMAC signature/webhook verification, constant-time compare), `POST /api/projects/[id]/payments` (order creation; business-only), `POST /api/payments/webhook` (raw-body signature check, idempotent, service-role), [`src/components/dashboard/payment-gate.tsx`](../../apps/web/src/components/dashboard/payment-gate.tsx) (the UI), and migration [`supabase/migrations/059_project_payments.sql`](../../supabase/migrations/059_project_payments.sql) (payments ledger; clients can never mark a payment "paid" — only the signed webhook can).
- **Tests:** [`tests/unit/razorpay.test.ts`](../../apps/web/tests/unit/razorpay.test.ts).
- ⚠️ **Not yet verified live:** order creation, the webhook, and Checkout can only be exercised with *your* Razorpay account. The server logic is unit-tested; the live path needs the §4.3 walkthrough.

## 4. Human-only deploy steps (do these before launch)

These need your accounts/credentials — I can't and shouldn't do them. Estimated total: **~1–2 hours**.

### 4.1 🔴 Create a dedicated PRODUCTION Supabase project
1. supabase.com → new project (region closest to users; strong DB password).
2. Enable **Point-in-Time Recovery / daily backups** (Database → Backups).
3. Copy Project URL, `anon` key, and `service_role` key for §4.5.
> Do **not** launch against the dev database. Prod must be isolated.

### 4.2 🔴 Apply all migrations to the prod DB (051 → 059)
From repo root, against the prod project:
```bash
supabase link --project-ref <PROD_PROJECT_REF>
supabase db push          # applies every migration in supabase/migrations
```
Verify these tables/RPCs exist afterward: `verification_checks`, `submit_verification` (055), `project_stage_items` (054), `social_account_claims` (058), `project_payments` (059). If any are missing, verification/payments routes will 500.

### 4.3 🟡 Razorpay (only if you want in-app payments at launch)
1. dashboard.razorpay.com → complete KYC/activation (required for live keys; can take a day — start early).
2. Settings → API Keys → generate. You get `key_id` (starts `rzp_live_`) + `key_secret`.
3. Settings → Webhooks → add `https://<your-domain>/api/payments/webhook`; subscribe to **`payment.captured`** and **`order.paid`**; set a **webhook secret**.
4. Put the values in §4.5. Then do one live test payment on a real project's advance-payment gate and confirm the gate opens automatically.
> Skip this and V1 runs in honest manual mode — perfectly fine to launch. Add Razorpay later with zero code changes.

### 4.4 🟡 Upstash (rate-limiting correctness on serverless)
1. upstash.com → create a Redis DB → REST API section.
2. Copy `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` into §4.5.
> Skip and limits still work per-instance (looser). Strongly recommended for prod.

### 4.5 🔴 Set environment variables in your host (Vercel/Azure)
Set for the **production** environment (never commit these):
```
APP_ENV=production
NEXT_PUBLIC_APP_URL=https://<your-domain>
NEXT_PUBLIC_SUPABASE_URL=...            # prod (§4.1)
NEXT_PUBLIC_SUPABASE_ANON_KEY=...       # prod
SUPABASE_SERVICE_ROLE_KEY=...           # prod, server-only
APIFY_TOKEN=...                         # verification (rotate — was shared in plaintext)
# Optional but recommended:
UPSTASH_REDIS_REST_URL=... / UPSTASH_REDIS_REST_TOKEN=...
NEXT_PUBLIC_SENTRY_DSN=... / SENTRY_DSN=...
# Only if using Razorpay:
NEXT_PUBLIC_RAZORPAY_KEY_ID=... / RAZORPAY_KEY_ID=... / RAZORPAY_KEY_SECRET=... / RAZORPAY_WEBHOOK_SECRET=...
```

### 4.6 🟡 Rotate the shared API keys
The **Apify token** and **HikerAPI key** were shared in plaintext during setup — regenerate both and use the new values. Fund **Apify** (~1,900 verifications per $5) at console.apify.com/billing; it degrades to manual review when empty (no crash).

### 4.7 🟢 Sentry project
sentry.io → new Next.js project → copy the DSN into `NEXT_PUBLIC_SENTRY_DSN` **and** `SENTRY_DSN` (§4.5). Trigger a test error and confirm it lands.
