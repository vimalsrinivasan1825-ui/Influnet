How it fits together

One backend, two front doors, nine outside services

The web app and the mobile app do not have separate backends. Both call the same 114 API routes inside the Next.js container. Those routes read and write one Supabase Postgres database as the signed-in user, so row-level security (RLS) decides what each person sees. The admin CRM is part of the same web app, behind admin checks. Only a few things bypass the API: sign-in, live updates, chat and card checkout go straight from the phone or browser to Supabase, Stream and Razorpay.

Where code goes when you push

Two environments, and production is the second one

Each branch deploys its own web container and its own database. A push to staging also publishes an over-the-air mobile update to every installed app. That is the red arrow below, and it is the least guarded path in the whole system.

What the database holds

72 tables in nine groups

Chat messages live on Stream, not in these tables; messages is only the history from before Stream. Projects are campaign_projects with a numeric id. There is no collaborations table. Every table has RLS on. On profiles and business_profiles, users may read only an allow-listed set of columns. Asking for any other column fails the whole query, not just that field.

New since the 17 September audit

The earlier audits (docs/operations/GO_LIVE_AUDIT_2026-09-17.md, APP_STORE_READINESS_2026-09-17.md) still stand, and their open items are folded into the work order below. These items are new, or have changed since then.

High

F1 · Production is 129 commits behind, so the September fixes aren’t live

Checked live: staging.influnet.io/legal/privacy and /legal/terms → 404. First request 23.4 s, next 0.25 s (the minimum-replica fix is in dev's deploy file but hasn't run). Production database at migration 147; dev at 160.

Fix: the dev → staging PR, but only after F2 and F3 below are in (Phase 1).

High

F2 · Deleting an account destroys finished projects, payment records and invoices, for both sides

006_campaign_projects.sql:6–7: both owner_user_id and counterparty_user_id are ON DELETE CASCADE. project_payments (059) and project_documents (124) cascade from the project. The new self-delete (api/profile/route.ts) blocks only active projects, so a brand that deletes after completion wipes the creator's invoice too. Your draft terms promise to keep tax records.

Fix: a migration that changes both foreign keys to SET NULL and anonymises the leaving party. Invoices and payments stay. Must ship before real users can delete accounts, since the in-app delete button is already built.

High

F3 · Merging to staging pushes an OTA update to every installed app, with no approval and no rollout

.github/workflows/mobile-update.yml: any push to staging that touches apps/mobile or packages runs eas update --channel production. The waiting merge carries a month of mobile changes. Changes that need a native build, such as the privacy manifest and permissions, can't travel by OTA at all.

Fix: make the production-channel job manual behind the production GitHub Environment approval, and publish at a percentage (EAS Update rollouts), for example 10% → 100% after a day of clean Sentry.

High

F4 · The admin password commit is on GitHub now

2d91fb65 is on origin/dev and on a Dependabot branch. The 17 Sep plan to squash it before pushing no longer applies.

Fix: rotating the password is the whole fix. Don't rewrite shared history. Also move ADMIN_CREDENTIALS.local.txt out of the repo folder into a password manager.

Medium

F5 · Nothing automated watches production

weekly-health.yml probes dev.influnet.io only. Broadcast, maintenance and nudge jobs each take a single endpoint secret, so they run against one environment. There is no uptime monitor in the repo for the production URL.

Fix: UptimeRobot on the production health URL (10 min), and point those three endpoint secrets at production.

Medium

F6 · Account deletion leaves chat on Stream, and two screens still point to a dead mailbox

lib/account-deletion.ts never deletes the Stream user, so chat history stays on Stream's servers. mailto:support@influnet.in is still in apps/mobile/app/settings.tsx:434 and apps/web/src/app/delete-account/page.tsx:82, and that domain has no mail server (MX record).

Fix: delete the Stream user in hardDeleteAccount, and switch both links to a mailbox that receives mail.

Medium

F7 · Mobile has no automated tests, and the store build reports no crashes

0 test files under apps/mobile (web has 49 files, 532 tests). The production profile in eas.json sets no EXPO_PUBLIC_SENTRY_DSN or EXPO_PUBLIC_POSTHOG_KEY. Store icon is still 512 px with transparency.

Fix: add the keys and a 1024 px opaque icon in the next native build, plus a small smoke-test suite run in the cloud (Phase 3).

Progress

Already fixed since 17 Sep

iOS privacy manifest added · unused microphone, Face ID and overlay permissions removed · real in-app account deletion with an active-project guard and a tombstone record · hiding Pro purchase in store builds is in progress (uncommitted changes in billing.tsx, use-upgrade.ts, eas.json).

Your routine once live

  • Daily, 2 min: Sentry new issues, uptime, admin → Reports queue (the stores expect action on reports within 24 h).
  • Weekly, 30 min: admin → Health and Vendors, Resend bounce and complaint rate (stop sending above ~2% complaints), Razorpay captures vs gates, Supabase egress, merge patch-level Dependabot PRs.
  • Monthly, 1 h: run the E2E suite against dev (with NOTIFY_EMAILS_ENABLED=false), and review costs.
  • Quarterly: restore drill, credential review, renewals.

Break-glass switches

  • One email template misbehaving → EMAIL_DISABLED_TEMPLATES=<id>
  • All email → NOTIFY_EMAILS_ENABLED=false
  • A vendor failing or billing out of control → admin → Vendors, switch it off
  • A broadcast gone wrong → BROADCAST_DRY_RUN=true or the vendor_expo_push switch
  • Paid plans misbehaving → SUBSCRIPTIONS_ENABLED=false
  • A bad web deploy → redeploy the previous image; don't revert commits under pressure
  • A bad mobile OTA → republish the previous update group (needs F3's manual gate to be calm)
  • A stuck project → record_stage_signoff() / revoke_stage_signoff(), never hand-edit stage_progress
