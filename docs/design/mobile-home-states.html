Why “Before” looks flat Page #f6f7f9 against card #ffffff is roughly a 3% luminance step, and only 2 of the 8 cards on Home passed raised — which itself mapped to shadows.card at 5% opacity and 3px blur. The gradient wash used to paper over this. Now the ground is deeper and every card carries a shadow.
Card is two views in the app, and has to be overflow:'hidden' keeps an unpadded card’s edge-to-edge rows inside its rounded corners — and on iOS it clips the view’s own shadow to nothing. Shadow on the outer box, clipping on the inner. A single view would have shipped a change that is correct on Android and absent on every iPhone.
One elevation, no exceptions Two surfaces built their own box instead of using Card, so the redesign passed them by: the “Waiting on others” list group, and the loading skeleton. Both carry the card shadow now — a flat skeleton replaced by a lifted card makes the screen appear to pop upward the moment data lands.
The device screens stay light in dark mode Deliberate: the app has no dark theme, so these are photographs of a light-mode screen. The board around them follows your system setting.

The strip shows five of twelve, and says so The design's five steps — Collaboration started, Project discussion, Content planning, Content confirmation, Payment terms — are not the real sequence. The full flow has 12 stages, and its third is advance_payment: a money gate that only opens on a signed Razorpay webhook. Drawing five unlabelled steps would tell a brand the deal is nearly a third done when it is one twelfth in, and would hide the payment gate entirely. Same visual, real labels, windowed on the current stage, with “Step 2 of 12” underneath.
One line of backend, no new query /api/collabs already selects current_stage for the annotation pass and then drops it when building project. Adding it to that object is the only server change this screen needs.
Initials, not photos The two profile embeds on that route select name, role only — there is no avatar URL in this payload. The design's initial circles are what we can actually draw, so they are drawn as designed rather than as a broken image.

The icon is classified from the title A keyword table maps a project’s own words onto an icon and a colour: reel / video / shoot → clapperboard, skincare / beauty / serum → bottles, sneaker / shoe → footwear, plus food, travel, fashion, tech, fitness and jewellery, falling back to a folder. Colour follows the CATEGORY, not a hash, so two skincare projects look like two skincare projects — the icon means something rather than merely differing.
No project has an image, and none can There is no image column on campaign_projects. Every cover here is generated (ui/cover-art.tsx) with the classified icon on it. If an upload ever lands, the hero swaps to the photo and the icon stays as the badge.
Two fields need backend work due_date exists on the table but the project detail route does not select it — one line. “Deliverables: 2” is not backed at all: the deal stores deliverables as free text, not a count, so this shows the advance instead, which is real. The mockup’s “1 Creator” is dropped — a project always has exactly one, so a tile that can only ever read 1 is not a number.
The timeline is real, including the times stage_progress records each side’s sign-off with a timestamp, which is where “took 2 days”, who signed and when all come from. Payment rows come from the ledger. Nothing on that screen is inferred.

The border is transparent, not removed Keeping the 1px width means every box is exactly the size it was, so nothing reflowed — and it leaves the slot open for the cards that DO want a visible ring. The accent border on a decision card sets borderColor alone and still lands; that is the pink ring on “Confirm the shoot date”.
Two layout bugs went with it Stat tiles were rendering over a thousand points tall on device. flex: 1 is flexBasis: 0%, Yoga wraps by measuring basis, so all six tiles landed on one line before minWidth inflated them — and only the tiles without an onPress stretched, because a pressable one has a content-sized Pressable absorbing it. The grid chunks into explicit rows of two now. The pipeline strip’s last step is also cut by the card edge rather than stopping short of it.
